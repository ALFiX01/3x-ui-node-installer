# Установка ноды 3x-ui

Скрипт устанавливает 3x-ui, Nginx, сертификаты Let's Encrypt и VLESS Reality. В конце выводит данные входа, параметры добавления ноды в основную панель и VLESS-ссылку.

## Требования

- Чистый VPS с Ubuntu 22.04 или 24.04, без установленной 3x-ui и Nginx.
- Доступ по SSH под `root`.
- Два разных домена: для панели и сайта-маскировки. Их A-записи должны указывать на публичный IPv4 VPS. AAAA-записи нужно удалить, проксирование Cloudflare — отключить (DNS only).
- В firewall хостинга должны быть разрешены входящие TCP-порты `80`, `443` и `8443`. Сохраните доступ по SSH.

## Запуск с GitHub

Подключитесь к VPS по SSH. 

```bash
apt-get update && apt-get install -y curl ca-certificates
curl -fL --proto '=https' https://raw.githubusercontent.com/ALFiX01/3x-ui-node-installer/main/install_3xui_node.sh -o /root/install_3xui_node.sh
sed -i 's/\r$//' /root/install_3xui_node.sh
bash -n /root/install_3xui_node.sh && bash /root/install_3xui_node.sh
```

Команда скачивания предназначена для публичного репозитория. Переносить файл вручную не нужно. Перед запуском можно посмотреть его содержимое: `less /root/install_3xui_node.sh`.

Скрипт запросит оба домена и email для Let's Encrypt. Домены вводите без `https://`, порта и пути.

На домене сайта-маскировки появится адаптивная страница входа в личный кабинет без регистрации. Это статическая заглушка: форма показывает ошибку входа, введённые логин и пароль не отправляются на сервер и не сохраняются кодом страницы. Она не связана с авторизацией в панели 3x-ui. Все стили и скрипты встроены в страницу, внешние ресурсы не загружаются.

## После установки

Данные сохраняются в `/root/3xui-node-credentials.txt` с доступом только для root:

```bash
cat /root/3xui-node-credentials.txt
```

Для добавления ноды используйте блок с параметрами API панели: домен панели, HTTPS, порт `443`, Base Path и API-токен. Порт `8443` используется клиентским VLESS-подключением.

Проверьте подключение с основной панели и работу VLESS-клиента из другой сети. Не публикуйте файл с паролем, API-токеном и VLESS-ссылкой.

## Продолжение после сбоя

После устранения причины ошибки запустите тот же файл:

```bash
bash /root/install_3xui_node.sh --resume
```

Домены и реквизиты повторно вводить не нужно. Состояние хранится в `/root/.3xui-node-install/`: каталог имеет права `700`, файл `state.json` — `600`. Он содержит пароль панели и ключи Reality. Храните этот каталог вместе с резервной копией сервера и не публикуйте его.

Продолжение использует прежние логин, пароль, Base Path, UUID, ключи Reality и Short ID. Certbot повторно использует сертификаты, если срок не требует продления. Перед созданием inbound скрипт запрашивает список из панели: если первый запрос создания выполнился, но ответ потерялся, существующая запись проверяется и используется повторно. Сохранённый API-токен проверяется без повторного выпуска.

Конфигурация Nginx должна совпадать с одним из двух вариантов, созданных этой установкой. При изменённом конфиге, другом клиенте или ключе Reality, пропавшем ранее проверенном inbound скрипт останавливается. Сначала выясните причину расхождения; удалять состояние или править флаги этапов для обхода проверки нельзя. Одновременные запуски блокируются.

Есть два случая, когда автоматическое продолжение намеренно ограничено:

- Если прервалось выполнение внешнего установщика 3x-ui, нельзя достоверно определить, какие его действия завершились. Скрипт не запускает его повторно. Нужны ручная проверка `/usr/local/x-ui`, базы `/etc/x-ui/x-ui.db` и `journalctl -u x-ui` либо восстановление чистого VPS из снимка.
- Если создание API-токена началось, но его полный вывод не сохранился, скрипт не выпускает другой токен. Проверьте раздел API Tokens в панели. Для продолжения администратор должен сохранить действующий токен в `/root/.3xui-node-install/api-token-output` в формате `apiToken: ЗНАЧЕНИЕ`, с владельцем root и правами `600`. Затем повторите `--resume`; токен пройдёт проверку API.

Установки, выполненные старой версией скрипта без `state.json`, автоматически не подхватываются. Изменения сервера при ошибке не откатываются. После успешной установки `--resume` также сверяет состояние; это не режим обновления или ремонта произвольно изменённой панели.

## Автоматические проверки

На Linux нужны Bash, Python 3, OpenSSL и ShellCheck:

```bash
bash -n install_3xui_node.sh
shellcheck --severity=warning install_3xui_node.sh
python3 -m unittest discover -s tests -v
```

GitHub Actions выполняет эти команды на Ubuntu 22.04 и 24.04 при push и pull request. Тесты запускают настоящие функции и основной сценарий скрипта в отдельных процессах Bash, но заменяют пакеты, systemd, DNS, Certbot и API панели локальными имитациями. Они проверяют сбои и продолжение, отсутствие повторного создания inbound и токена, сохранение идентификаторов и отказ при конфликтующей конфигурации.

Эти проверки не устанавливают 3x-ui на настоящий VPS, не обращаются в Let's Encrypt и не подтверждают соединение реального VLESS-клиента. Для проверки релиза целиком нужна отдельная одноразовая VM.
